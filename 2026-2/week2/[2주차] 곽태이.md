# ▪︎ ER-Diagram

#### **ER-Diagram이 뭘까?**

- DB에 어떤 데이터를 저장할 지, 그 데이터끼리 어떤 관계인지 그림으로 설계한 것.
- **개체(Entity)**: 저장해야 할 대상. DB 테이블 하나, Spring에서는 `@Entity` 클래스 하나가 된다. 예를 들어 쇼핑몰이라면 회원, 상품, 주문 같은 것들.
- **속성(Attribute)**: 엔티티가 가진 정보. 회원이라면 이름, 이메일 같은 것. 테이블의 컬럼
- **기본키(PK, Primary Key)**: 행 하나를 유일하게 구분하는.
- **관계(Relationship)**: 엔티티끼리의 연결.

# ▪︎ API 명세서

#### API란?

- 클라이언트와 서버 간 데이터를 교환하는 규칙이자 방법
- SW 간 유연한 통합과 확장을 가능하게 하여 개발 시간을 줄이고 효율성을 높임

#### API 명세서가 뭘까?

- **프론트엔드와 백엔드가 주고받는 약속을 적은 문서**. 어떤 기능을 쓰려면, 어떤 주소로, 어떤 방식으로, 어떤 데이터를 보내면, 어떤 응답이 온다를 미리 정해 두는 것.
- API의 기능, 엔드포인트(요청 URL), HTTP메서드(GET, POST 등), 요청과 응답형식, 인증방식, 오류처리 방법 등 API 사용에 필요한 모든 정보를 체계적으로 정리한 문서

#### 왜 필요할까?

1. 백엔드와 프론트엔드 개발자들 간의 소통을 원활하게 하여 협업에 굉장히 필요함
2. 개발과 테스트, 문서화, 유지보수를 효율적으로 할 수 있음
3. 일관성 유지 가능

#### API 명세서 작성 방법

![image.png](image%202.png)

1단계 - 기능 목록을 API 단위로 쪼개기

- 핵심 기능 하나가 API 하나가 되는 경우가 많다. 기능마다 "누가 무엇을 요청하고 뭘 돌려받나"를 생각하면 된다.

2단계 - 각 API의 HTTP Method를 고른다

- Method는 "무슨 행동을 하는가"를 나타낸다.
- **GET**: 조회 (데이터를 가져오기만 하고 바꾸지 않음)
- **POST**: 생성 (새 데이터 등록)
- **PUT**: 전체 수정 (자원의 모든 필드를 교체)
- **PATCH**: 부분 수정 (일부 필드만 변경)
- **DELETE**: 삭제

3단계 - API Path(주소)를 설계한다

- **API Path** - 서버를 큰 건물, 그 안의 자원(todo, category 같은 데이터)을 방이라고 생각. Path는 그 건물 안에 몇호실로 가하는 안내…..
    
    API = Method + Path이고 Path가 같더라도 Method가 다르면 다른 API이다. 
    
- **쿼리 파라미터(Query Parameter) -** URL 뒤에 물음표(`?`)와 함께 붙는 키-값(Key-Value) 쌍
API 엔드포인트에 쿼리 파라미터를 붙이면 주로 결과를 조회하거나 필터링하는 데 사용된다.
    
    판단 기준은 "결과가 특정 자원 하나인가, 조건에 맞는 여러 개인가”
    
    `?` 앞은 **"어떤 자원을 가져오는가"**, `?` 뒤는 "그 자원 중에서 어떤 조건으로 거르는가"
    
- **API Path를 잘 작성하는 방법?**
1. `명사` 사용하기(어떤 자원에 대한 것인가 생각해보기)
2. 여러개의 리소스에 대해서는 `복수형 명사`로 작성하기
3. 일관되고 `직관적인 이름` -> 직관적일수록 협업/ 유지보수/ 확장이 쉬워짐
4. 하이픈(-)사용 + 소문자
5. 기능대신 `자원 중심`으로 경로 만들기 (RESTful 원칙)

4단계 - 요청(Request)과 응답(Response)을 정한다

- **요청**: 어떤 데이터를 어디에 담아 보내는가. id는 주소에, 새로 만들거나 수정할 내용은 보통 **요청 본문(Body)에 JSON**으로 담아. 필수값이 뭔지도 정해야 해. 앞에서 category를 필수로 정했으니 todo 등록 요청에 뭐가 들어가야 하는지 연결해서 생각해 봐.
- **응답**: 성공하면 뭘 돌려줄 건가(조회 결과, 생성된 데이터 등). 슬라이드 코드의 `ApiResponse`처럼 응답 형식을 통일해 두는 경우도 많아.
- **상태 코드**: 결과를 숫자로 알려줘. 자주 쓰는 것만 보면, 200(성공), 201(생성 성공), 204(성공했고 돌려줄 내용 없음), 400(잘못된 요청), 404(대상 없음)가 있어. 각 API마다 성공했을 때와 실패했을 때 어떤 코드를 줄지 생각해 봐.
