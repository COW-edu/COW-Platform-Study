# ⭐ 용어 정리
## Entity
DB에 저장하고 관리할 데이터의 구조를 코드로 표현한 것이다.
즉, 어떤 데이터를 어떤 형태로 저장할지 정의한 것이다.
## ER-Diagram
Entity들 사이의 관계를 그림으로 나타낸 것이다.
즉, 데이터 종류끼리 어떻게 연결되는지 보여주는 설계도이다.
## SQL
데이터베이스에 명령을 내리기 위해 사용하는 언어이다.
## API 명세서
프론트엔드와 백엔드가 어떤 방식으로 데이터를 주고받을지 정리해 놓은 문서이다.
요청 주소(URL), 요청 방식(GET, POST 등), 전달할 데이터, 응답 데이터 등의 내용을 작성한다.
## DTO
Data Transfer Object의 약자로, 데이터를 주고받기 위해 사용하는 객체이다.
API를 통해 데이터를 주고받을 때 어떤 데이터를 전달할 것인지 구조를 정의하는 역할을 한다.
쉽게 말하면 데이터를 주고받기 위한 상자인 것이다.
## Controller
사용자의 요청을 가장 먼저 받아 요청에 맞는 처리를 할 수 있도록 연결해 주는 역할을 한다.
예를 들어 사용자가 Todo 추가를 요청하면 Controller가 해당 요청을 받아 필요한 로직으로 전달한다.
## Postman
API를 직접 요청하고 응답을 확인하며 테스트할 수 있는 프로그램이다.
프론트엔드 화면이 완성되지 않아도 API가 정상적으로 작동하는지 확인 가능하다.
## Port
하나의 컴퓨터 안에서 실행되고 있는 특정 프로그램이나 서비스를 구분하기 위한 번호이다.
## Docker
프로그램과 프로그램 실행에 필요한 환경을 하나로 묶어 동일한 환경에서 실행할 수 있도록 도와주는 기술이다.
개발자의 컴퓨터마다 환경이 달라 발생할 수 있는 문제를 줄이는 데 사용할 수 있다.
## .yml
YAML 형식으로 작성된 설정 파일에 사용하는 확장자이다.
프로그램의 여러 설정값을 작성하거나 Docker 등의 환경을 설정할 때 사용할 수 있다.
## Parameter
함수나 API가 작업을 수행하는 데 필요한 값을 전달하기 위해 사용하는 입력값이다.
# ♥️ 느낀 점
이번 학습을 통해 백엔드에서 주로 사용하는 용어를 접하면서 프론트와 백엔드의 데이터를 주고받는 과정에 대해 이해할 수 있었다. 
아직 익숙하지 않은 용어가 많기 때문에 계속 접하면서 익힐 필요가 있다고 느꼈다.
