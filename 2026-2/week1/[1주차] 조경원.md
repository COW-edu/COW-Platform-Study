# 백엔드의 역사와 핵심 개념

## 1. 백엔드의 등장

> **HTML을 미리 만들어 놓지 말고, 요청이 들어올 때 서버가 만들자.**

### 정적 웹

```text
요청 → 미리 저장된 HTML 반환
```

### 동적 웹

```text
요청 → 서버에서 프로그램 실행 → HTML 생성 → 반환
```

---

## 2. 백엔드 프로그래밍의 5가지 기본 개념

1. **변수**: 데이터를 담는다.
2. **조건문**: 조건에 따라 실행할 작업을 결정한다.
3. **반복문**: 같은 작업을 반복한다.
4. **함수**: 여러 작업을 하나로 묶는다.
5. **데이터 타입**: 데이터의 종류를 구분한다.

```text
변수 → 조건문 → 반복문 → 함수 → 데이터 타입
```

---

## 3. 데이터베이스

관계형 데이터베이스의 대표적인 예로 **MySQL**이 있다.

| 용어 | 설명 |
|---|---|
| Table | 행과 열로 구성된 데이터 표 |
| Query | 데이터를 조회하거나 변경하기 위한 명령어 |
| Schema | 데이터베이스의 구조와 정의 |

대표적인 조회 명령어로 `SELECT`가 있다.

---

## 4. MVC 패턴

> **복잡해진 코드를 역할별로 분리하자.**

MVC는 코드를 역할에 따라 Model, View, Controller로 분리하는 설계 방식이다.

| 구성 요소 | 역할 |
|---|---|
| Model | 데이터 조회 및 저장 |
| View | 사용자에게 보여줄 화면 생성 |
| Controller | 요청을 받고 필요한 처리를 연결 |

### 비즈니스 로직

비즈니스 로직은 서비스가 실제로 수행해야 하는 핵심 규칙과 처리 과정을 의미한다.

쇼핑몰 주문 과정을 예로 들면 다음과 같다.

```text
재고 확인 → 결제 → 재고 감소 → 배송 처리 → 이메일 발송
```

## 5. REST API

REST API는 클라이언트가 서버에 데이터를 요청할 수 있는 창구이다.

| 구성 요소 | 설명 |
|---|---|
| JSON | 데이터를 주고받는 형식 |
| Endpoint | API 요청을 보내는 주소 |
| CRUD | 데이터를 생성·조회·수정·삭제하는 기본 작업 |

### CRUD

| 작업 | 의미 |
|---|---|
| Create | 데이터 생성 |
| Read | 데이터 조회 |
| Update | 데이터 수정 |
| Delete | 데이터 삭제 |

## 7. HTTP의 Stateless 특성

HTTP를 이용한 서버 통신은 기본적으로 **상태를 기억하지 않는 Stateless 방식**이다.

즉, 서버는 이전 요청에서 사용자가 로그인했다는 사실을 자동으로 기억하지 않는다. 이를 해결하기 위해 세션과 쿠키가 사용된다.

---

## 8. 세션과 쿠키

- **세션(Session)**: 로그인 정보를 서버에 저장한다.
- **쿠키(Cookie)**: 세션을 찾을 수 있는 번호표를 브라우저에 저장한다.
- 브라우저는 서버에 요청을 보낼 때 쿠키를 함께 전달한다.

```text
로그인 성공
    ↓
서버에 세션 저장
    ↓
브라우저에 쿠키 저장
    ↓
이후 요청에 쿠키 포함
```

---

## 9. 인증과 인가

- **인증(Authentication)**: 사용자가 누구인지 확인하는 과정
- **인가(Authorization)**: 사용자가 해당 기능을 이용할 권한이 있는지 확인하는 과정

```text
로그인 → 인증

일반 사용자의 관리자 페이지 접근 차단 → 인가
```

---

## 10. JWT

JWT는 점(`.`)으로 구분된 세 부분으로 이루어진 토큰이다.

```text
Header.Payload.Signature
```

| 구성 요소 | 역할 |
|---|---|
| Header | 토큰의 종류와 서명 방식 |
| Payload | 사용자 ID와 같은 정보 |
| Signature | 토큰의 위조 여부를 확인하는 서명 |

> JWT의 Header와 Payload는 암호화된 것이 아니라 인코딩된 것이다. 따라서 비밀번호와 같은 민감한 정보를 담으면 안 된다.

---

## 11. 비밀번호 해싱

비밀번호는 원본 그대로 데이터베이스에 저장하면 안 된다.

해시 함수를 이용해 원본을 알아보기 어려운 값으로 변환한 후 저장해야 한다.

> 보안은 백엔드 개발에서 선택이 아니라 필수이다.

---

## 12. 비동기 처리와 동시성

요청을 하나씩 순서대로 처리하면 사용자가 많아질수록 대기 시간이 길어진다.

비동기 처리는 데이터베이스나 외부 서버의 응답을 기다리는 동안 다른 요청을 처리하는 방식이다.

### 관련 개념

- **동시성**: 여러 작업을 번갈아 처리하는 성질
- **멀티스레드**: 여러 작업자가 일을 나누어 처리하는 방식
- **이벤트 루프**: 한 작업자가 여러 일을 빠르게 번갈아 처리하는 방식
- **Non-Blocking**: 하나의 작업이 기다리는 동안 다른 작업을 진행하는 방식

---

## 13. 캐시

같은 데이터를 요청할 때마다 데이터베이스에서 조회하면 비효율적이다.

자주 사용하는 데이터를 빠른 메모리에 미리 저장해 두는 것을 **캐시(Cache)**라고 한다.

```text
요청 → 캐시에 데이터 있음 → 즉시 응답

요청 → 캐시에 데이터 없음 → DB 조회 → 캐시에 저장 → 응답
```

### 주요 기술

- **Redis**: 메모리를 사용하는 대표적인 캐시 저장소
- **TTL(Time To Live)**: 캐시 데이터가 유지되는 시간
- **CDN(Content Delivery Network)**: 이미지와 동영상 등을 사용자와 가까운 서버에서 제공하는 기술

---

## 14. 트랜잭션

트랜잭션은 서로 관련된 여러 작업이 모두 성공하거나 모두 실패하도록 보장하는 기능이다.

### 계좌 이체 예시

```text
A 계좌에서 10만 원 차감
          +
B 계좌에 10만 원 추가
```

- 두 작업이 모두 성공하면 **Commit**
- 작업 도중 오류가 발생하면 **Rollback**

### ACID 원칙

| 원칙 | 의미 |
|---|---|
| Atomicity | 모든 작업이 전부 성공하거나 전부 실패해야 한다. |
| Consistency | 데이터는 정해진 규칙과 일관성을 유지해야 한다. |
| Isolation | 동시에 실행되는 작업이 서로 방해하지 않아야 한다. |
| Durability | 완료된 작업은 서버가 종료되어도 유지되어야 한다. |

## 15. 서버 확장

사용자가 증가하면 서버 한 대만으로 모든 요청을 처리하기 어려워진다.

### 수직 확장

서버의 CPU와 메모리 등을 더 좋은 부품으로 교체하여 성능을 높이는 방식이다.

```text
기존 서버 → 더 좋은 성능의 서버
```

### 수평 확장

같은 역할을 하는 서버의 개수를 늘리는 방식이다.

```text
서버 1대 → 서버 여러 대
```

### 로드 밸런서

로드 밸런서는 들어오는 요청을 여러 서버에 골고루 분배한다.

```text
                  ┌→ 서버 1
사용자 → 로드 밸런서 ─→ 서버 2
                  └→ 서버 3
```

## 16. 모놀리스와 마이크로서비스

### 모놀리스

로그인, 주문, 결제 등 모든 기능이 하나의 서버와 코드에 포함된 구조이다.

- 구성이 비교적 단순하다.
- 한 기능의 문제가 전체 서비스에 영향을 줄 수 있다.
- 일부 기능만 변경해도 전체 서비스를 다시 배포해야 할 수 있다.

### 마이크로서비스

기능별로 서비스를 나누어 독립적으로 운영하는 구조이다.

```text
로그인 서비스
상품 서비스
주문 서비스
결제 서비스
```

### 함께 사용되는 기술

- **API Gateway**: 들어온 요청을 적절한 서비스로 전달한다.
- **Message Queue**: 처리할 작업을 임시로 보관하고 순서대로 전달한다.

메시지 큐를 사용하면 특정 서비스가 잠시 중단되어도 작업이 사라지지 않는다. 서비스가 복구되면 보관된 작업을 다시 처리할 수 있다.

## 17. 배포와 운영

### 배포

개발자가 작성하거나 수정한 코드를 실제 사용자가 이용하는 서버에 반영하는 과정이다.

### CI/CD

코드를 저장소에 올렸을 때 테스트와 배포 과정을 자동으로 실행하는 방식이다.

### Docker

코드와 실행 환경을 함께 포장하여 개발자의 컴퓨터와 실제 서버에서 동일하게 동작하도록 도와주는 기술이다.

### 운영에서 중요한 요소

- 개발 환경과 운영 환경 분리
- 서버의 동작을 확인할 수 있는 로그 기록
- 서버 상태 모니터링
- 오류 발생 시 원인 확인 및 대응
