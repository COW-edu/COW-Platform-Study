# [1주차] 라혜준

초기에 웹 서버는 저장된 HTML 파일을 그대로 전달하기만 했다. 그런데 방명록이나 검색처럼 사용자마다 결과가 달라야 하는 기능이 필요해지면서, 서버가 요청이 들어올 때마다 화면을 직접 만들기 시작했고 이것이 백엔드의 출발점이다. CGI, PHP, JSP 같은 기술이 이 역할을 맡았다. 이때 쓰이는 백엔드 언어들은 이름은 달라도 변수, 조건문, 반복문, 함수, 데이터 타입이라는 같은 뼈대 위에 서 있어서, 하나를 익히면 나머지는 쉽게 넓혀 갈 수 있다.

서버가 화면을 만들려면 데이터를 어딘가에 보관해야 했기 때문에 표 형태의 관계형 데이터베이스가 등장했다. 기능이 늘어 코드가 뒤엉키자 데이터, 화면, 흐름 제어를 나누는 MVC 구조로 정리했고, 주문 처리처럼 서비스의 핵심 규칙을 담당하는 부분을 비즈니스 로직이라 부르게 됐다. 이후 모바일 앱이 등장하면서 서버는 HTML 대신 JSON 형식의 데이터를 제공하는 API 역할로 바뀌었고, 이때부터 백엔드는 데이터를 공급하고 프런트엔드는 화면을 만드는 식으로 역할이 나뉘었다. PHP, 파이썬, 자바, Go, Node.js 등 여러 언어와 프레임워크가 있지만 정답은 없고, 팀의 역량과 서비스 규모, 개발 속도에 맞춰 고르면 된다.

서비스가 커질수록 새로운 문제가 차례로 나타났다. 서버가 사용자를 기억하지 못하는 문제는 세션과 쿠키, JWT로 해결했고, 인증과 인가, 비밀번호 해싱으로 보안을 갖췄다. 속도가 느려지자 비동기 처리와 캐시, CDN을 도입했고, 계좌이체처럼 데이터가 꼬이면 안 되는 작업에는 트랜잭션을 적용했다. 사용자가 더 늘어나자 서버를 여러 대로 늘리는 수평 확장과 기능별로 서버를 나누는 마이크로서비스가 등장했고, 수많은 서버를 관리하기 위해 자동 배포와 도커, 모니터링 같은 운영 기술이 자리 잡았다. 결국 백엔드의 모든 발전은 그때그때 마주친 문제를 해결한 결과이다.
