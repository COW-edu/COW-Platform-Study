# 웹의 시작 
- 웹은 문서
- 서버 = 파일 보관함. 서버라는 컴퓨터에 HTML 파일
저장해두고 주소를 입력하면 파일을 꺼내줌
- 방명록. 파일을 미리 만들어놓은 방법으로는 불가능

# 동적 웹
- 서버가 입력을 받아서 생각하고 다른 결과를 주어야함 →
백엔드
- 요청이 들어올 때 파일을 만들자 → 서버가 HTML을 직접 만들기 시작
- CGI스크립트 → 방명록 글 저장 → 새로 만든 HTML 보관 → 제조
- 서버 사이드 렌더링 - 서버쪽에서 화면을 만들어줌
- 서버가 보관하는 역할에서 제조로 바뀜. 동적 웹에 등장

# 제조는 뭘로 하는 걸까? 백엔드 언어
- 백엔드 언어 1. 변수 2. 조건문 3. 반목문 4. 함수 5.데이터타입
- 클래스: 관련된 함수와 변수를 묶어서 거기에 이름을 붙이는 구조
- 예외처리: 오류가 나면 어떻게 대응할지 정하는 것

# 어디에 저장할까?  데이터 베이스
- 텍스트 파일 한계 ->  관계형 데이터 베이스. my sql
- 표, 명령어(쿼리), 스키마(구조)

# MVC 역할별로 파일을 나누자
- 모듈(데이터를 꺼내고 저장)
- 뷰(사용자에게 보여줄 html만들기)
- 컨트롤러(요청이 들어오면 어떤 데이터를 꺼내서 화면을 보여줄지 정함)
- 비지니스 로직 - 처리과정. 서비스 핵심 규칙

# API의 탄생
- API: 데이터 요청 창구
- 데이터 형식 json 
- endpoint 창구 주소 의미있는 이름을 붙이자
- CRUDL 

# HTTP 웹에서 서버와 통신하는 방식은 기본적으로 상태(state)가 없다
- 서버는 기억력이 없다. 
- 세션 - 서버 메모리에 저장
- 쿠키 - 브라우저에 저장
- state가 없는 HTTP위에 state를 얹는 기술이 세션과 쿠키 → 로그인 유지

# 인증, 인가
- 로그인 - 인증(누구인지)
- 접근 제어 - 인가(권한 있는지)
- 서버 메모리에 로그인 정보를 저장하다 보니 서버가 여러대가 되면 어려움
- JWT(제이슨 웹 토큰): 로그인 정보를 암호화해서 사용자에게 줌. 요청할 때 그 정보를 서버가 풀어서 확인
- 비밀번호 → 해싱 원본을 알아볼수없는 다른 형태로 변환 저장

# 비동기 처리 동시성
- 다른 요청 처리.(기다리는동안)
- 멀티 스레드 - 직원 여러명  이벤트 루프 - 직원 한명이 동시에 여러일을 번갈아 빠르게
- 논 블로킹 - 하나가 막혀있어도 다른 것들이 진행

# 캐시
- 캐시 - 자주 요청되는 데이터를 빠른 메모리에 올려놓고 바로 메모리에서 꺼내기
- 레디스 
- TTL: 캐시에 올려놓은 데이터의 유효시간 - 갱신필요
- CDN: 이미지나 동영상 전세계에 복사해놓고 가까운곳에서 받음

# Transaction $ Scaling
- 트랜잭션: 이 작업은 전부 성공 전부 실패. 중간에 오류가 나면 롤백 → 커밋
- ACID - atomicity(원자성), consistency(일관성), isolation(격리성), durability(지속성)
- 수직확장(서버를 더 좋은 거로 바꾸는 거)
- 수평확장(서버를 더 많이 늘리는 것)
- 로드 밸런서 - 요청을 여러 서버로 골고루 분배

# 분산 서비스. 마이크로 서비스
- 분산 서비스 - 구조 여러 서버가 나눠서 일하는 구조.
- 모놀리스 - 기능 하나를 바꾸려면 다같이 업데이트를 해야함.
- 마이크로 서비스: 기능별로 서버를 나누자 - 독립적 운영
- API 게이트웨이: 사용자 요청 정리 - 서비스 연결 창구
- 메세지 큐에 메모를 남겨놓기도 함(서버다운됐을때메모)

# 서비스 관리 배포
- 배포: 서비스 업데이트
- CI/CD: 코드 수정 - 테스트 - 서버 배포 자동화 
- 도커: 환경포장기술 - 코드와 환경을 한번에 포장
- 로그 - 서버의 기록
- 모니터링 - 로그의 기록을 보는 것
