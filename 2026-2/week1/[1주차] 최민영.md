# 1주차 강의 기록
## 인터넷 vs 웹
인터넷 = 전 세계 컴퓨터들을 서로 연결해 주는 네트워크 인프라.(도로망)
웹 = 도로를 이용하는 우편 시스템, 인터넷을 기반으로 소포를 URL이라는 주소에 따라 배달하는 것을 말한다.(문서 공유 시스템)

## 하이퍼 텍스트
문서 안에서 다른 문서로 이동하는 링크를 심어서 클릭 한번으로 정보를 넘나들 수 있게 하는 것
문서 작성 규칙 → HTML(구조)
문서 주소 → URL(주소) - 모든 문서마다 고유한 주소를 부여해서 어디서든 접근 가능하게 함.
문서를 주고받는 방법 → HTTP(통신) - 문서를 요청하고 받는 통신 규칙

모든 파일에 있는 스타일을 전부 하나 하나 변경(유지 보수 지옥) + 시각적인 스타일(디자인)까지 넣으니 코드 엉망. → **CSS(표현)**

## Javascript
이벤트(반응) = 사용자가 클릭, 키 입력, 스크롤 등 뭔가 했을 때 발생하는 신호를 잡을 수 있다.
돔dom(조작) = html 파일을 읽는 순간 페이지 속 모든 요소들을 지도처럼 저장해 놓는다. 내부 지도(DOM)

## 브라우저 전쟁(소프트웨어 전쟁)
크로스 브라우저 이슈
브라우저가 html 파일을 위에서 아래로 읽으면서 페이지 전체 요소를 파악한다. 스타일 정보 정리도 한다.
그릴 목록 추리기 = 읽은 내용 중에서 실제로 화면에 보여줄 것들만 골라낸다.
레이아웃 = 각 요소가 화면 어디에 어떻게 놓일 지를 계산한다.
리플로우
자바 스크립트로 돔을 수정하면 레이아웃을 다시 수정해야 한다.
리플로우가 많이 일어나면 버벅거려서 성능이 뚝뚝 떨어진다.
프론트엔드의 최적화 핵심 중 하나가 리플로우를 얼마나 줄이냐
라이브러리(jQuery = 브라우저마다 달랐던 돔 조작 방법을 하나로 통일해줌 즉, 크로스 브라우저 문제를 상당 부분 해결해 주었다.)

## React
- 개발자는 데이터 관리에만 집중하고 화면 업데이트는 리액트가 알아서 해주는 구조
- 라이브러리
1. 추상화 Abstraction = 복잡한 동작은 안에 숨겨 놓고 우리는 간단한 명령어만 쓴다.
2. 재사용성 = 카드 틀 하나만 만들어 놓고 내용만 바꿔서 찍어낸다.(리액트의 컴포넌트)
3. 상태 관리(state) = 앱이 기억해야 하는 모든 정보를 버그를 막기 위해 규칙을 정해 두는 방법

코드 공유 및 관리 문제 → Node.js 등장 (자바 스크립트를 브라우저 밖에서도 실행할 수 있게 해 주는 런타임(코드가 실제로 돌아가게 하는 환경))
npm = 프로그래밍 세계의 앱 스토어. 전 세계 개발자들의 라이브러리 패키지들이 등록되어 있다. → NPM install react 한 줄이면 리액트가 프로젝트에 설치된다.
package.json(npm이 사용하는 프로젝트의 명세서)
dependacy  의존성 = 라이브러리가 다른 라이브러리에 의존하는 식의 연쇄 관계를 뜻한다.

## 빌드 build
트랜스파일링 = 배포 전에 최신 문법으로 쓴 글을 누구나 읽을 수 있는 표준 말투로 자동 번역해 주는 과정
번들링 = 수백 개로 쪼개져 있는 파일을 하나 또는 몇 개로 묶어주는 작업을 한다.
트리쉐이킹 = 번들링할 때 한 번도 안 쓴 코드를 자동으로 솎아내는 과정
프로덕션 최적화 = 파일 크기를 최대한 줄이는 작업
package.json은 빌드 과정을 거쳐야 배포가 된다.

mpa
spa single page application - 초기 로딩이 느려짐 & seo 약해짐(spa는 ux를 얻고 seo를 잃었다)
클라이언트 사이드 라우팅

## 프론트엔드 직무
리액트 같은 프레임워크로 복잡한 ui 로직을 짜고 백엔드 서버에 api를 호출해서 데이터를 받아오고 그 데이터로 화면을 그리는 모든 과정을 담당한다.
프론트엔드는 ui 아키텍처를 설계하고 상태 관리, 성능 최적화, api 통신
ssr vs csr
ssr = 서버에서 미리 html을 완성해서 브라우저에 보내주는 방식 / 화면 바로 표시(seo를 얻고 서버 부하가 늘었다)
csr = 브라우저에서 자바 스크립트가 실행되면 화면을 그리는 방식
하이드레이션 = ssr로 받은 정상적인 html에 js를 심어서 인터랙티브하게 만드는 과정이다.

## ⭐[정리]
웹 = 문서 공유 시스템
인터넷 위에 링크로 연결된 문서들을 올리는 것
html이 뼈대를 세우면 css가 옷을 입히고 javascript가 움직이게 만들어줬다.
브라우저마다 다르게 보이는 문제 때문에 표준화가 시작되었다.
코드가 점점 복잡해지자 리액트 같은 라이브러리가 등장했다.(for 중복 제거)
npm으로 코드를 부품처럼 가져다 쓸 수 있게 되었다.
빌드 과정이 생기면서 내가 작성한 코드와 실제로 배포되는 코드가 달리지기 시작했다.
spa = 페이지 깜빡임 없이 앱처럼 동작 (검색 안 잡히는 문제)
ssr 등장
프론트엔드는 디자인을 구현하는 사람이 아니라 브라우저와 사용자 경험을 설계하는 독립적인 기술자이다.
